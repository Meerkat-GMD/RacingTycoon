# 탭별 성장 지도 배치 검증

2026-09-24. 전체 특성을 한 장에 펼치던 지도를 6개 탭으로 나누었다. 비용·효과·구매 조건·저장 ID는 기존 `Progression` 카탈로그를 그대로 사용한다. 새 좌표는 표시 전용 `UpgradeTreeLayout`에 분리했다.

| 탭 | 특성 수 | 같은 탭 연결선 | 다른 탭 선행 조건 |
| --- | ---: | ---: | ---: |
| 가게 운영 | 5 | 1 | 1 |
| 솜사탕 제작 | 7 | 6 | 1 |
| 기계와 맛 | 4 | 3 | 3 |
| 알바 | 5 | 4 | 4 |
| 장소와 판매 | 6 | 5 | 6 |
| 카트 | 3 | 2 | 0 |
| 합계 | 30 | 21 | 15 |

같은 탭의 선행 조건은 아래쪽 특성으로 향하는 직선 화살표로 표시한다. 다른 탭의 선행 조건은 대상 특성 이름 아래의 클릭 가능한 조건 칩으로 표시한다. 칩으로 옮겼다는 이유로 선행 조건을 삭제하거나 구매 판정을 바꾸지 않는다.

## 자동 검증

실행 명령: `./Tools/test-upgrade-tree-layout.ps1`

- 실제 카탈로그의 30개 특성이 정확히 한 탭에 포함된다.
- 실제 카탈로그의 모든 36개 선행 조건이 21개 내부 연결선 또는 15개 외부 조건 칩으로 표현된다.
- 1048×550 지도 안에 아이콘·이름·외부 조건 칩이 모두 들어간다.
- 특성 영역끼리 겹치지 않는다. 각 영역은 중심 X±88, Y−32부터 Y+69+23×외부 조건 수까지 보수적으로 잡는다.
- 모든 내부 화살표가 아래로 향하고, 실제로 보이는 수직 길이가 최소 14px 이상이다.
- 내부 연결선끼리 교차하거나 같은 구간에 겹치는 경우가 각 탭에서 **0개**다.
- 다른 특성의 아이콘·이름·조건 칩 영역을 통과하는 연결선은 **0개**다. 화살촉·두께를 포함하도록 해당 영역을 6px 더 넓혀 검사한다.
- 검사에 사용하는 선분은 렌더링과 동일하게 시작점 `(부모.X, 부모.Y + 69 + 23×외부 조건 수 + 5)`와 끝점 `(자식.X, 자식.Y − 38)`이다.

검증 결과: **15개 통과, 0개 실패**. 로그: `Logs/upgrade-tree-layout-tests.txt`.

## 실제 플레이어 검증

- `Tools/test-progression.ps1`: 성장 규칙 **14개 통과**.
- Unity Editor 통합 검사 **58개 통과**.
- `Tools/verify-progression.ps1 -OutputFolder Logs/CrossingFreeTreeSmoke`: **171개 통과**.
- 6개 탭 클릭, 다른 탭 선행 조건으로 이동, 이동 시 돈·구매 상태 불변, 대상 특성 강조, 선행 조건 미충족 구매 차단, 선행 특성 구매 후 종속 특성 활성화를 실제 EventSystem 레이캐스트로 확인했다.
- 확대·축소·드래그·전체 보기와 기존 영업/기계/알바/저장 복원 시나리오도 통과했다.
- 구매 완료 후에도 호버에 모든 선행 특성과 완료 상태가 표시된다.
- 새 탭 활성화와 다음 클릭을 같은 프레임에 실행하던 검증은 실제 조작처럼 클릭 사이에 한 프레임을 두도록 수정했다. 실제 최상위 레이캐스트 검사는 그대로 유지했다.

독립 코드/화면 검토에서 1600×900의 모든 탭을 확인했고, 최종 검증에서 1280×720의 밀집된 장소·판매 화면도 확인했다. 교차, 라벨 겹침, 잘림이 없다. UI 이름과 내부 화살표만 상시 표시하고, 외부 조건은 짧은 이름·달성 표시·이동 버튼으로 표시한다. 가격과 효과는 호버로 확인한다.

# 솜사탕 장사·레이싱: 아웃게임 성장 결정 기록

갱신일: 2026-09-24

현재 단계는 기획 정리다. 이 문서는 대화에서 확정된 규칙, 현재 코드 상태, 후속 설계 제안을 구분한다. 가격·효과량·노드 배치가 확정된 구현 명세는 아니다. 이전 문서의 10분 영업·무료 설탕 전체 공급 등과 달라지는 새 기획을 기록하며, 실제 코드 반영 여부는 별도로 확인한다.

## 1. 전체 목표와 반복 흐름

- 1차 목표: 성장 트리를 끝까지 진행하는 데 약 **2~4시간**인 완결형 성장 분량.
- 이후 목표: 같은 게임을 **10~20시간** 분량으로 확장.
- 한 번의 영업시간: 최초 **3분**. 영업시간 증가 업그레이드가 있으므로 매번 고정 3분은 아니다.
- 기본 흐름: 아웃게임에서 특성 구매·장비와 알바 준비 → 영업 시작 → 레이싱과 솜사탕 장사 → 마감 정산 → 아웃게임으로 복귀.

2~4시간과 10~20시간은 한 번의 영업 길이나 개발 기간이 아닌, 전체 성장 콘텐츠의 목표 플레이 시간이다.

## 2. 확정된 게임 규칙

| 분야 | 사용자와 확정한 내용 |
|---|---|
| 최초 상품 | 딸기맛만 판매하며 소·중·대 구분 없이 시작한다. |
| 특성 재화 | 장사로 번 돈으로 영구 특성을 구매한다. 별도 특성 포인트는 없다. |
| 특성 형태 | 노드와 연결선으로 이루어진 성장 그래프. 선행 특성을 구매해야 다음 특성을 구매할 수 있다. |
| 노드 구매 횟수 | 수치 강화 노드는 여러 레벨, 새로운 기능을 해금하는 노드는 한 번 구매한다. |
| 선행 조건 | 선행 특성의 1레벨을 구매하면 다음 노드의 구매 자격이 열린다. 다음 노드는 자신의 가격을 따로 지불한다. |
| 기계·장비·알바 획득 | 해당 트리 노드를 구매하면 즉시 획득한다. 해금 후 상점에서 다시 구매하는 비용은 없다. |
| 기본 설탕 | 기본 딸기 설탕은 투입 비용 0원. 상위 설탕을 해금한 뒤에도 기본 설탕을 선택할 수 있도록 유지한다. |
| 유료 설탕 | 유료 설탕은 기계에 투입할 때 비용을 지불한다. 알바의 자동 생산에도 설탕 비용이 적용된다. |
| 설탕 등급 | 모든 맛에 공통으로 해금된다. 설탕 등급에 따라 성장 가능한 크기가 제한된다. |
| 기계 | 여러 대를 동시에 보유·가동한다. 기계에 따라 레이싱 맵이 달라지며, 특정 맛과 크기에는 요구 기계 등급이 있다. |
| 직접 운전 | 플레이어가 한 대를 직접 운전한다. 영업 중에도 다른 기계로 옮겨 직접 운전할 수 있고 레이싱 맵이 전환된다. |
| 알바 배치 | 다른 기계는 알바가 자동 생산한다. 알바 등급이 기계의 요구 등급을 충족해야 한다. |
| 알바 메뉴 | 플레이어가 기계별로 만들 맛·크기를 지정하면 해당 메뉴를 반복 생산해 진열한다. 주문을 보고 메뉴를 자동 선택하는 방식은 아니다. |
| 알바 비용 | 고용과 등급 업그레이드에만 비용을 지불한다. 매 영업의 급여는 없다. |
| 젓가락 강화 | 제작 속도 증가, 설탕 소비량 감소, 품질·판매가 증가의 세 효과를 모두 포함한다. |
| 영업 간 초기화 | 다음 영업으로 넘어갈 때 진열대 제품, 모든 기계의 남은 설탕과 제작 중 솜사탕을 초기화한다. |
| 영구 유지 | 돈, 구매한 특성·기계·장비, 고용·강화한 알바 등 영구 성장 결과를 유지한다. |

관리 화면에서는 보유 장비 선택, 알바 배치, 기계별 생산 메뉴를 설정한다. 트리 구매와 동일한 장비를 다시 구매시키지 않는다.

## 3. 성장에 포함할 항목

사용자가 요청한 업그레이드 범위:

- 영업시간 증가.
- 손님 대기시간 증가.
- 설탕 맛 종류 해금.
- 모든 맛에 공통인 설탕 등급 해금과 최대 솜사탕 크기 확장.
- 기계 구매·등급에 따른 맵과 제작 가능 제품 확장.
- 카트 업그레이드.
- 젓가락의 제작 속도·설탕 효율·품질 강화.
- 광고를 통한 손님 도착 속도 증가.
- 진열대 개수 증가.
- 알바 고용과 등급 강화.
- 장사 위치에 따른 손님과 주문 종류 확장.

카트의 구체적인 강화 능력, 각 항목의 최대 레벨·가격·효과량은 아직 정하지 않았다. 젓가락의 세 효과를 한 노드에서 동시에 올릴지, 계열 안의 개별 노드로 나눌지도 배치 설계에서 확인한다.

## 4. 1차와 이후 확장을 나누는 설계 제안

다음은 목표를 실현하기 위한 제안이며, 노드 수나 콘텐츠 수가 확정된 것은 아니다.

- 1차에도 제작·판매·성장뿐 아니라 사용자가 결정한 여러 기계와 알바 운영을 포함한다. 등급 수와 지역 수를 조절하여 전체 성장 분량을 2~4시간에 맞춘다.
- 이후에는 상위 설탕 등급, 기계, 지역, 추가 성장 노드를 덧붙여 10~20시간으로 확장한다. 단순히 같은 구매의 가격만 올려 반복 시간을 늘리는 방식은 피한다.
- 노드의 고유 ID, 연결 관계, 최대 레벨, 가격, 효과를 데이터로 관리하는 구성을 제안한다. 이후 콘텐츠 추가와 기존 저장의 구매 이력을 연결하기 위한 목적이다.
- 처음부터 수백 개의 노드 수를 정하지 않는다. 시험 영업에서 실제 판매량·순이익·다음 구매까지의 시간을 확인한 뒤 성장 간격을 조정한다.
- 무한 성장, 환생, 오프라인 수익은 이번 대화에서 요청하거나 확정한 기능이 아니다.

## 5. 제안 상태이거나 추가 결정이 필요한 규칙

아래 내용을 사용자 확정 사항으로 취급하지 않는다.

| 항목 | 확인할 내용 또는 제안 |
|---|---|
| 기계 전환 | 각 기계의 설탕·제작 상태 유지, 영업 타이머 계속 진행, 이전 기계에 알바가 있으면 자동 생산 재개·없으면 정지를 제안했다. 영업 중 기계 전환 자체는 확정이다. |
| 알바의 잔금 부족 | 지정된 유료 설탕을 살 돈이 부족하면 생산을 멈출지 등의 처리. 무료 딸기 설탕으로 자동 변경하는 규칙은 합의하지 않았다. |
| 부분 투입과 실패 | 탱크에 10g 미만만 들어갈 때의 요금, 가득 찼거나 잘못된 맛으로 투입이 거절됐을 때의 과금, 설탕 교체·비우기의 환급 처리. |
| 크기와 주문 | 크기 구분이 열리는 조건과 처음의 단일 상품을 소·중·대로 연결하는 방법. 제작 가능한 메뉴만 주문하게 하는 것은 제안 상태다. |
| 성장 상한 | 설탕·기계 등급이 허용하는 최대 크기에 도달한 뒤 설탕 소모를 멈추는 규칙은 제안 상태다. |
| 여러 선행 노드 | 한 노드로 여러 연결선이 들어올 때 선행 노드 전부가 필요한지, 하나만 필요할지 아직 정하지 않았다. |
| 노드 구성 | 가지 분류·위치·개수, 젓가락 효과 배분, 레벨별 비용·효과량, 구매 취소·초기화 가능 여부. |

아웃게임 화면의 `특성 트리 / 장비·알바 관리 / 영업 시작` 구분과, 노드의 `구매 완료 / 구매 가능 / 돈 부족 / 선행 조건 부족` 표시는 UI 제안이다.

## 6. 이번 대화에서 확인한 현재 코드와 차이

코드 정적 검토 기준이며, 이번 기획 정리에서 게임을 실행하거나 코드를 수정하지 않았다.

- 현재 기본 진입은 바로 영업을 시작한다. 영업 준비·영구 성장 구매 화면을 거치는 반복 흐름이 필요하다. 관련 코드: `Assets/CottonCircuit/Scripts/GameController.cs`, `ShiftController.cs`.
- 현재 영업은 600초, 설탕 3맛이 모두 열려 있고 투입 비용이 없다. 소·중·대 주문을 순환해서 생성한다. 관련 코드: `Assets/CottonCircuit/Scripts/Core/ShopShift.cs`.
- 현재 업그레이드·진열대 구매 함수와 저장 데이터는 남아 있지만, 기본 영업 UI에는 구매 화면이 연결되어 있지 않다. 관련 코드: `Core/Economy.cs`, `SplitUI.cs`, `ShiftUI.cs`.
- 현재 설탕·제작 중 제품은 하나의 영업 상태에 들어 있다. 여러 기계를 전환하려면 기계별 생산 상태와 알바 배치를 구분해서 보관해야 한다.
- 현재 품질은 판매가를 바꾸는 값이다. 새 기획의 설탕 등급·기계 등급과 같은 의미로 재사용하면 안 된다.
- 현재 저장 검사는 영업시간·대기시간 등을 고정값으로 검사한다. 성장에 따라 바뀌는 값과 새 트리·기계 상태를 처리하도록 저장 규칙도 함께 변경해야 한다. 관련 코드: `SaveStore.cs`.
- 현재 판매 시 즉시 돈을 받는다. 마감 정산에서 같은 매출을 다시 지급하지 않도록 하고, 유료 설탕 도입 후에는 매출과 재료비·순이익을 구분한다.

## 7. 조사한 참고 게임

아래는 공식 Steam 소개로 확인한 범위다. 참고작의 세부 선행 조건이나 모든 강화의 통화가 우리 게임과 같다는 뜻은 아니다.

| 게임 | 확인한 구조 | 적용 참고점 |
|---|---|---|
| [Nodebuster](https://store.steampowered.com/app/3107330/Nodebuster/) | 자원을 얻어 업그레이드를 구매하고 성장 트리를 탐색한다. | 영업 성과를 성장 그래프에 투자하는 흐름. |
| [To The Core](https://store.steampowered.com/app/1988550/To_The_Core/) | 연료가 소진되기 전 자원을 모으고 연료·내구도·성능을 강화한다. | 제한된 영업 후 다음 영업의 활동 시간과 생산력을 강화하는 흐름. |
| [Digseum](https://store.steampowered.com/app/3361470/Digseum/) | 유물을 발굴·전시하여 방문객을 유치하고, 수입으로 박물관과 발굴 능력을 강화한다. | 제작 능력과 판매·손님 유치 능력에 나눠 투자하는 구조. |
| [Keep on Mining!](https://store.steampowered.com/app/3769130/Keep_on_Mining/) | 자원으로 트리의 영구 강화를 구매하며 자동 채굴 시설을 해금한다. | 기계와 알바 구매를 통해 자동 생산이 확장되는 구조. |

첨부 이미지는 연결된 특성 그래프의 표현 참고 자료다. 원본 게임의 정확한 명칭이나 화면 속 모든 구성요소를 이번 게임의 요구사항으로 확정하지 않았다.

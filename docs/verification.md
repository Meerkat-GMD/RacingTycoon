93개 실행 확인에는 게임 동작, 버튼 호출, 화면 범위·텍스트 넘침 검사와 테스트 준비 조건이 포함된다. 테스트는 별도 저장 폴더에서 실제 `GameController`의 가속·조향 입력과 uGUI 버튼의 `onClick`을 실행한다. 물리 키보드·마우스 자동화나 사람의 조작감 평가는 수행하지 않았다. 실제 게임에는 테스트용 자동 조향이 없다.

## 실제 게임에서 확인한 흐름

- 첫 손님 주문 → 만들러 가기 → 카트 주행 → 솜사탕 완성 → 가게 복귀 → 재고 선택 → 건네기 → 가격과 팁 지급.
- 딸기·소다·바닐라 각각 작은 60g/큰 120g, 총 여섯 레시피를 실제 주행 경로로 완성. 제품의 주된 맛과 크기를 검사하며 샘플 맛을 덮어쓰지 않는다.
- 회색 길에서는 전진해도 생성량 0. 정지·위치 복귀도 무료 생산 없음. 드리프트 충전과 부스트 작동.
- 가게 복귀만으로 자동 판매되지 않음. 잘못된 제품과 중복 전달은 코인·재고를 변경하지 않음.
- 손님은 제작 중 기다리고, 일시정지·결과 화면에서는 대기 시간 정지. 만료된 주문은 제품을 삭제하지 않음.
- 팁·만족도·판매·진열대 저장, 진열대 6→9→12칸, 꽉 찬 재고의 출발 제한.
- 재고 정리 첫 클릭은 확인 안내만 표시, 두 번째 클릭은 선택 제품만 제거. 빈 칸이 생기면 다시 제작 가능하며 저장 후 재고 수 유지.
- V1 저장의 코인·제품·기존 업그레이드를 보존해 V2로 이전. 손상된 V2는 원본 덮어쓰기 금지.

기본 속도 18의 별도 순수 주행 시뮬레이션에서도 여섯 레시피를 9.68–23.86초에 만들었다. 이는 테스트 운전자의 기록이며 모든 플레이어의 완성 시간을 보장하는 값은 아니다. 코스 길이는 그대로 유지하고 수집량을 기존 대비 5배로 조정했으며, 설탕통 단계마다 15%를 추가한다.

## 화면과 3D 에셋

가게·제작 주행·완성·도움말·전달·확장 진열대 화면을 확인했다. 최종 캡처는 `docs/screenshots/orders-*.png`에 있다. 1600×900, 1280×720, 1280×960, 1920×820에서 버튼이 화면 안에 있고 텍스트 넘침이 없음을 검사했다. 결과 전환 시 중앙 솜사탕을 바로 보여주며, 일시정지 안내가 계속하기 버튼을 가리지 않는다.

Blender 원본 `Art/Blender/ShopProps.blend`와 FBX 3종은 미터 크기·재질·원점·유효 메시·외향 법선·FBX 재임포트를 검증했다. 기본/레이싱 에셋을 합해 총 15종이다.

## 배포와 범위

최신 실행 파일은 `Builds/OrderPreview/CottonCircuit.exe`다. 이전 `Builds/Windows/CottonCircuit.exe`가 사용 중이어서 별도 폴더로 빌드했다. 저장 경로는 동일하므로 이전 게임을 닫은 뒤 최신 버전을 실행한다.

배포 빌드는 `-Release`로 자동 검증 코드를 제외한다. 전체 플레이와 시각 검증은 개발 플레이어에서 수행했다. 코스는 하나이며 직접 조향·드리프트·지름길·세 맛·두 크기·주문 경영을 제공한다. 추가 맵, 경쟁 AI, 직원 자동화, 가게 자유 배치는 이번 범위에 포함하지 않는다.

최종 배포는 종료 코드 0, COTTON_RELEASE_SUCCESS 97050845, uild-info.json의 Release 구성을 확인했다.

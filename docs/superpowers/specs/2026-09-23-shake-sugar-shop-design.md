# 설탕 흔들어 투입·거리별 솜사탕·하루 영업 설계안

2026-09-23. 사용자가 "10분으로 해주고 작업 진행해줘"로 구현 진행을 승인했다. 하루 길이는 10분으로 수정하고 나머지 제안 기본안을 초기 구현값으로 사용한다. 첨부 그림의 빨간 글씨는 기능 설명이며 실제 게임 화면에 그대로 표시하지 않는다.

## 사용자와 확정한 내용

- 화면 왼쪽은 주행, 오른쪽은 가게 미리보기·손님·완성품 진열대·설탕 공급 영역으로 구성한다.
- 설탕 봉지를 주행 화면으로 드래그한 상태에서 위아래로 흔들면 설탕이 투입된다. 단순히 놓는 동작만으로 투입하지 않는다.
- 설탕 봉지는 우선 무료·무제한 공급한다. 기계에 투입한 설탕은 생산하며 소모한다.
- 주행 화면에서 투입된 설탕의 맛과 남은 양을 확인할 수 있어야 한다. 설탕이 없으면 주행해도 솜사탕을 만들지 못한다.
- 한 바퀴마다 제품 하나를 자동 완성하는 방식에서, 여러 바퀴를 달리며 한 제품을 키우고 F로 꺼내는 방식으로 바꾼다.
- 제작 중인 솜사탕의 모습과 성장 상태를 표시한다. 크기는 생산에 기여한 주행거리에 따라 커진다.
- 최소 완성량에 도달하지 않아도 F로 꺼낼 수 있다. 판매 기준에 못 미친 제품은 판매할 수 없다.
- 손님은 맛과 A/B/C 크기를 주문한다. 사용자가 제시한 거리 예시는 A 1km, B 2km이며, 1km 미만 제품은 쓰레기통에 버려야 한다.
- 완성품을 손님에게 드래그해 맞는 주문을 전달하면 돈을 얻는다.
- 진열대 옆에 쓰레기통을 놓는다. 진열대의 솜사탕을 쓰레기통으로 드래그하면 버린다.
- 잘못된 솜사탕을 전달하면 손님이 화내는 대사를 하고, 약간의 지연 뒤 떠난다.
- 상단의 남은 시간은 하루 영업시간이다. 시간이 끝나면 그날의 장사를 마친다.

## 제안하는 세부 기본안

다음 수치와 예외 규칙은 사용자 확정사항이 아닌 초기 구현 제안이다. 조정 가능한 설정으로 분리한다.

| 항목 | 기본안 |
|---|---|
| 하루 길이 | 10분(600초). 일시정지 중에는 영업시간과 손님 반응 시간이 흐르지 않는다. |
| 크기 구간 | 0km 초과~1km 미만은 판매 불가, 1km 이상~2km 미만은 A, 2km 이상~3km 미만은 B, 3km 이상은 C. 큰 제품으로 작은 주문을 대체하지 않는다. |
| F 입력 | 생산량이 0이면 꺼내지 않는다. 생산량이 양수이고 진열대에 자리가 있으면 현재 제품을 꺼내고 새 제품의 누적 거리를 0으로 만든다. 차량의 위치와 속도는 유지한다. |
| 거리 인정 | 설탕을 실제 소비하며 전진한 거리만 인정한다. 정지·역주행·코스 복귀의 위치 이동·설탕 없는 주행으로 성장하지 않는다. 설탕이 이동 구간 중 소진되면 소진 전 구간만 인정한다. |
| 최대 크기 | C 도달 후에도 생산 거리는 늘어난다. 화면 표현의 크기와 렌더링 샘플 수는 제한해 화면 가림과 메모리 증가를 방지한다. |
| 흔들기 판정 | 주행 화면 안에서 봉지를 잡고 위/아래 왕복 각 방향으로 24 기준 픽셀 이상 움직이면 1회로 인식한다. 기준은 높이 900의 디자인 좌표다. 작은 떨림·가로 이동·화면 밖 움직임은 제외한다. 유효한 왕복마다 설탕 10g을 투입한다. |
| 설탕통 | 용량은 100g, 유효 주행 1m당 0.02g을 소비한다. 흔들기 1회는 500m 생산분이며 2회 투입하면 A의 최소량을 만들 수 있다. 초과 투입하지 않는다. 한 번에 한 가지 맛만 사용하며 같은 맛은 제작 중에도 보충 가능하다. |
| 다른 맛으로 전환 | 제작 중인 제품이 있으면 먼저 F로 꺼내도록 안내한다. 제품이 없는 상태에서 다른 맛의 봉지를 흔들면 남은 설탕을 새 맛으로 교체한다. 남은 원료는 무료이므로 별도 구매·환불 절차를 두지 않는다. |
| 정상 판매 | 주문의 맛과 크기가 모두 일치하면 제품 하나를 소비하고 코인을 한 번만 지급한다. |
| 손님 수와 대기 | 그림에 맞춰 한 번에 한 명을 응대한다. 정상 판매 또는 퇴장 후 2초 뒤 다음 손님이 온다. 별도의 손님 대기 제한은 이번 기본안에서 두지 않고 영업시간을 사용한다. |
| 초기 판매가 | A 30코인, B 60코인, C 90코인. 맛별 가격 차이와 팁은 두지 않는다. 기존 품질·가게 업그레이드 배율은 유지하되 기본 가격과 분리한다. |
| 오배송 | 판매 가능한 제품의 맛 또는 크기가 주문과 다르면 해당 제품을 소비하고 코인을 지급하지 않는다. 손님은 화내는 대사를 1.5초 표시한 뒤 떠난다. 반응 중에는 추가 전달을 받지 않는다. |
| 미완성품을 손님에게 놓기 | 판매 불가 안내를 표시하고 진열대로 돌려보낸다. 사용자가 지정한 쓰레기통 처리를 유도한다. |
| 잘못된 드롭 위치 | 제품을 원래 진열대로 돌려보내며 재고·코인은 바꾸지 않는다. |
| 쓰레기통 | 판매 가능 여부와 관계없이 제품을 버릴 수 있다. 쓰레기통 위에 놓기 전 대상 강조로 삭제 동작을 구별한다. |
| 진열대 포화 | F 추출을 거절하고 제작 중인 제품을 유지한다. 버리거나 판매해 빈자리가 생기면 F로 꺼낼 수 있다. 진열대가 찼다는 이유로 이미 만들던 제품을 없애지 않는다. |
| 영업 마감 | 주행·생산·손님 응대를 멈추고 당일 판매 수, 매출, 오배송 수, 폐기 수를 정산한다. 미처리 손님은 정리한다. 다음 날 시작 버튼으로 다시 영업한다. |
| 다음 날 이월 | 코인·진열대 제품·남은 설탕·제작 중 제품을 유지한다. 손님과 영업 타이머는 새로 시작한다. |
| 완주 보상 | 새로운 영업 모드에서는 랩 완주 코인과 랩마다 날짜 증가를 없애고 판매 수입과 실제 영업일 증가를 사용한다. |

설탕통 용량·흔들기 1회 투입량·거리당 소비량·판매가·영업시간은 위 표의 초기값을 사용하고, 수치 변경이 가능하도록 한곳에 모은다. 실제 조작 검증에서 수치를 조정하면 변경 이유와 결과를 기록한다.

## 화면 및 상호작용

### 왼쪽 주행 화면

- 기존 주행 화면, 미니맵, 속도계, 자동 주행 전환을 사용한다.
- 투입된 설탕의 맛·잔량과 제작 중 제품의 미리보기·누적 거리·현재 크기를 표시한다.
- F로 꺼내기 안내와 다음 크기까지 필요한 거리를 표시한다. 최소량 미만에서는 판매 불가 상태가 분명해야 한다.
- 봉지를 드래그하면 투입 가능한 주행 영역을 강조한다. 흔들기 인식과 설탕이 실제로 들어가는 순간에 시각 반응을 준다.
- 랩 완주율·맵별 고정 제품 크기·다음 생산 예약 등 이전 생산 규칙의 UI는 새 흐름에 맞춰 정리한다.

### 오른쪽 가게 화면

- 상단에 하루 남은 영업시간과 보유 코인을 표시한다.
- 가게 미리보기 아래에 손님과 주문 말풍선을 배치한다. 주문에는 맛과 A/B/C 크기를 함께 표기한다.
- 진열대 제품은 그림과 크기 표식을 함께 사용한다. 판매 불가 제품은 명확하게 구별한다.
- 쓰레기통은 진열대에서 가까우면서 손님 드롭 영역과 겹치지 않게 배치한다.
- 하단에 맛별 설탕 봉지를 둔다. 기존의 맛 선택 버튼 대신 봉지를 집어 흔드는 동작으로 생산 맛을 정한다.
- 재고 선택 후 건네기 버튼을 누르는 흐름은 직접 드래그하는 흐름으로 교체한다.

## 구현 범위와 순서

1. **생산 상태:** 투입 설탕·소비량·유효 주행거리·현재 제품·F 추출을 분리한다. 랩 완주를 생산 완료 조건에서 제외한다.
2. **제품과 손님:** A/B/C 및 미완성 제품 구분, 정상 판매, 오배송 반응, 쓰레기통 폐기를 추가한다.
3. **하루 영업:** 영업 중/마감 정산 상태와 하루 타이머를 추가한다. 날짜 증가와 수익 처리를 새 규칙에 연결한다.
4. **입력과 화면:** 봉지 흔들기, 제품 드래그, 드롭 대상, 상태 표시와 말풍선을 연결하고 첨부 그림을 기준으로 배치한다.
5. **저장과 호환:** 현재 저장의 코인·제품·업그레이드를 유지하면서 새 제품 크기·남은 설탕·제작 중 제품·영업 상태를 저장한다. 기존 60g/120g 제품은 A/B로 이전하는 안을 사용한다.
6. **실제 플레이 검증:** 생산부터 판매·오배송·폐기·마감·다음 날까지 한 흐름으로 확인한다.

현재 작업 폴더에는 이전 좌우 분할 화면 작업의 미커밋 변경이 있다. 구현 시 이를 현재 기준으로 사용하며, 무관한 변경을 되돌리지 않는다.

## 검증 기준

- 봉지를 집기만 하거나 주행 영역 밖에서 흔들면 설탕이 들어가지 않는다. 영역 안의 유효한 위아래 흔들기에만 반응한다.
- 설탕이 없는 주행과 역주행·복귀 이동으로 제품 크기를 늘릴 수 없다.
- 1km와 2km, 제안 기준인 3km 직전·정확한 경계·직후의 크기 분류가 일관된다.
- 여러 바퀴를 달려도 자동으로 제품이 생기지 않는다. F를 눌렀을 때만 진열대로 옮겨진다.
- F 반복 입력과 드롭 중복 이벤트로 제품이나 코인이 복제되지 않는다.
- 1km 미만 제품은 팔리지 않으며 쓰레기통으로 버릴 수 있다.
- 정상 주문은 한 번 판매되고, 오배송한 손님은 대사를 보인 뒤 지연 시간에 맞춰 떠난다.
- 진열대가 찼을 때 F를 눌러도 제작 중 제품이 사라지지 않는다.
- 일시정지·마감 이후에는 투입·성장·판매가 발생하지 않는다.
- 마감과 같은 프레임에 발생하는 전달은 영업 중인지 확인한 뒤 최대 한 번 처리한다.
- 저장 후 다시 실행해도 남은 설탕·제작 중 제품·영업시간을 이용한 중복 생산이나 중복 정산이 발생하지 않는다.
- 기존 지원 해상도에서 주행과 손님, 설탕 봉지, 쓰레기통 영역이 겹치지 않고 모든 드래그 대상에 접근할 수 있다.
